# Episode V5 — Scouting: run the overview survey and read the answers: narration draft

Written part: [Part 5](../05-scouting.md). About seven minutes. Each `[SLIDE]` line names the image on screen while
the lines under it are read. This is a draft for the episode kit, not the final script.

---

[SLIDE: title — "Scouting: run the overview survey and read the answers". Under it: "By the end, you can run a
first survey on each kind of source, and read what it found."]

Erin's first question is about the database. Is coco pharma alive, and what is in it?
Peter answers it with the cheapest stage, Scouting.

[SLIDE: S16 — the run dialog]

Open the database, click Scouting, then Survey and analyses.
Its overview survey is Database Scouting Scan. Three steps, and none of them fetch: it reads only the database's own
catalog.
Click Run. The dialog says what will run, and against what.
Nothing runs until you confirm. Leave both boxes unticked, and click Run.

[SLIDE: S17 — running]

The card shows the running mark, and the results arrive in the question rows as each step lands.
On the Quickstart, it takes a few seconds.

[SLIDE: S18 — the answers]

Back on Questions, the count has gone from one of nine answered to five of nine.
Is it alive? Thirty-four thousand writes and nearly three million reads. So yes.
Each answer says where it came from, and when.
Some carry a note in blue. Here, the account could read 261 of the 266 tables, so five of the counts are estimates.
Every count on this page is within what this account can see.

[SLIDE: S18b — the numbers behind this]

Click the numbers behind this, and you see each number the answer is built from.

[SLIDE: S18, with "statistics_freshness has not run" highlighted]

Read the words, not only the mark. This answer has a tick, but it says one part has not run, so it is partial.
And the questions this survey did not answer still say so. Not run means nobody has looked yet.

[SLIDE: S19 — OpenLineage's header]

A repository works the same way. Its overview is Scouting Survey.
Afterwards its header shows stars, forks, contributors and size.
Security reads not read. That is not zero. The step that reads it has not run.

[SLIDE: S20a — root folder attached]

The folder is different. Egeria leads its survey, so Egeria needs the folder first.
On Curate, Publish to Egeria. The button attaches the root folder, and nothing else.

[SLIDE: S20 — the folder survey]

Back on Scouting, click Survey. Egeria reads the folder, and keeps a survey report.
The card now says Egeria can read the folder, and counts 136 files.

[SLIDE: S20b — the files section]

Open Files to see what Egeria counted: thirty-six CSV files, twelve spreadsheets, and the rest.

[SLIDE: closing — "Next: Discovery, Assessment and Analysis". "What can go wrong: see part 5 of the written
tutorial."]

A first look at all three. Next, Peter asks whether coco pharma is already in the catalog.
