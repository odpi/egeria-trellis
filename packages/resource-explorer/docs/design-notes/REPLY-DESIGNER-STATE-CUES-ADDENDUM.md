# REPLY — Designer: the state-cues addendum, one collision (2026-10-08)

To ASK-DESIGNER-STATE-CUES-ADDENDUM.md. **Already ruled, and merged**:
`REPLY-DESIGNER-STATE-AS-VISUAL-CUE.md` carries it as its closing
addendum (commit 86180f8a, on main). This note exists so the ask has a
reply by its own name, and to answer the third option, which the addendum
didn't address.

**The ruling, as merged:** the word **"deleted"**, with "in Egeria ·
‹when›" on the row's detail line. **No glyph.** The row lowers, as a
left-out row does. The future form is **"will delete"**. `glyphs.js`'s
`removed` key becomes `deleted`, with its ∅ dropped. That's the design
session's interim, confirmed as the ruling.

**Why not a new glyph:** it's a state that ends a row's story, and it's
rare. A glyph is worth adding when a person scans for a state among many
rows, and nobody scans for this one.

**Why not fold it into □ "archived":** the two differ in what the person
can do *next*, which is what a cue is for. On the commit path today
(`evidence/MORNING-NOTE-GATE-2026-10-06.md`), an **archived** schema
"can't be re-included until Egeria restores archived elements". Choosing
it again is refused. For a **deleted** schema, the gate note names no
such refusal. If the builder confirms that re-including one simply
recreates it, then "gone from Egeria" is the same for both, but "can I
choose it again" isn't, so they keep separate words. If the builder finds
deleted is refused too, the case for folding is stronger, but the words
should still differ: Egeria restores each one by a different path.
Either way, folding would put what a person needs before pressing Include
into a second line they might not read.
