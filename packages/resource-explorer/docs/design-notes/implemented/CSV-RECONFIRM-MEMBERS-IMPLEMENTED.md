# CSV re-confirm: members already in the investigation (implemented)

Found by the owner's gate walk of CSV in/out (PR #441): re-importing the same file previewed
"3 already registered" correctly, but the confirm still offered "Add these 3 to <investigation>",
and confirming reset the rationale and state of members the owner had since edited.

Environment proof: `resource_explorer.__file__` printed
`/Users/dwolfson/localGit/egeria-v6/trellis-re-csv-reconfirm/packages/resource-explorer/resource_explorer/__init__.py`.

## What changed
- `batch_io.preview_file(..., investigation="")`: reads the investigation's real member rows
  (`investigation_working_set_slug` + `list_working_set_members`, read only; no working set is
  created by previewing) and marks each already-registered line `in_investigation`; adds
  `counts.already_in_investigation` and echoes `investigation`. The preview route takes
  `investigation` in its body.
- `fileSelection()` (db-server-discovery.js): an already-registered row counts toward N and is
  offered only when it is not yet in the chosen investigation. A scope export imported into a
  second investigation still offers its rows (the gate's check 4). The flag is trusted only for
  the investigation the preview was planned against; changing the investigation dropdown re-plans.
- Summary reads "3 already registered (3 already in <name>)"; such rows have no tick box and say
  "already in <name>, nothing to add". When N is 0 the button reads "Nothing to add" (disabled),
  or "Apply these N changes" when proposed changes are ticked.
- `ProjectRegistry.add_working_set_member(..., keep_existing=False)`: with `keep_existing=True`
  an existing member keeps its rationale and state (the arguments only fill an empty one); a
  first-time add writes them either way. Only `batch_io.apply_import` passes it. Every other
  caller (disposition moves in registry.py, `POST /investigations/{slug}/members`, repair.py,
  tests) is an explicit edit and keeps overwrite.

## Tests
