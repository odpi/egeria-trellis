# SLICE — The next Analytic Library steps Egeria can dispatch (2026-10-15)

From the design session for the PR/CI session's builder, on the owner's
word of 2026-10-15, after `re-database-staleness` passed live (step 3).
Companion to the case-3 slice. Each candidate is a `SurveyStep` with a
`StepManifest` in `trellis-analytics`, declared by the generator, read-only
on the resource, reading RE's stored rows only through the typed reads in
`survey_step_host.STEP_ODS_METHODS`. Where a candidate needs a typed read
that does not exist, it is named and is the first line of that
candidate's work; no step runs SQL of its own.

## Ranking rule

Zero-fetch first (no connection to the resource), typed reads that exist
or are one method, a nothing-to-derive outcome that is a plain absence,
and a result that maps onto an Egeria annotation type without changing
its meaning (follow Egeria's lead). Candidates that need names and
comments of hundreds of tables are later, because their typed read is a
wide one.

## 5.1 Pieces, per candidate (the same five lines each)

| # | Piece |
|---|---|
| L1 | The step package under `packages/trellis-analytics/examples/steps/<name>/` with its manifest: request type, questions answered (stable ids), perspectives, purpose from `VALID_PURPOSES`, family, `credential_tier: read_only`, `nothing_to_derive_guard`, the measures it declares |
| L2 | The typed read it needs, added to `STEP_ODS_METHODS` as parameterised SQL RE owns, with a test that the method refuses anything but its parameters |
| L3 | The declaration generated by `generate_engine_host_declaration.py` from the manifest; equality test |
| L4 | The step's result mapped to the annotation types above, with the as-of and the caveat sentence on every measure |
| L5 | Registration in the engine host's library steps; the three guards |

## 5.2 Tests that fail first, per candidate

1. Manifest round trip: declaration equals manifest; request type unique
   across the library and the registries.
2. The typed read returns the rows the step needs and nothing else; a
   step calling any other method fails the host's test.
3. Nothing-to-derive: with the absence the guard names, the step
   completes `survey-invalid` with the sentence and publishes nothing.
4. The measure: a fixture with known rows produces the known numbers,
   the as-of equals the newest input row's, and a counter-reset or
   missing timestamp produces the caveat, never a silent zero.
5. The annotation shape: type name, measure names and the step's
   `producingStep` match the design table; one read-back fixture from a
   live report.

## 5.3 Gate (live, the owner's write round)

For each candidate, the owner triggers its type on coco_pharma from
Dr.Egeria: `survey-completed` with a report whose annotations match the
`step_runs` row, Understanding showing the run as a library step; then
the same trigger on a throwaway database with one snapshot only:
`survey-invalid` with the sentence. Five candidates, one gate each, in
rank order; a candidate that fails its gate does not block the next.

Each is a package under `packages/trellis-analytics/examples/steps/<name>/`, found through the `trellis.analytics`
entry point, declared by `generate_engine_host_declaration.py` in `docs/dr-egeria/engine-host/library/<name>.md`.

| Step | Request type | Typed read | Measures (Egeria type) |
|---|---|---|---|
| `statistics_freshness` | `re-statistics-freshness` | `table_activity_snapshots(slug, limit=1)` | per table (ResourceMeasureAnnotation); `statistics_freshness_summary` for the database (ResourceMeasureAnnotation) |
| `hub_tables` | `re-hub-tables` | `table_keys(slug)` | per table, foreign keys in and out (ResourceMeasureAnnotation); `hub_table_proposal` (ClassificationAnnotation, `classificationName: "hub table"`, values in `properties`, `contentStatus` DRAFT) |

Departures from the table above, by the 2026-10-15 ruling the staleness fix follows: the nothing-to-derive guard is
`survey-completed` for all three. One snapshot, no keys captured or nothing stored is an absence recorded on the
report with its sentence ("not measured · one activity snapshot only; a rate needs two", "not measured · no keys
captured; hubs cannot be derived", "not measured · no table statistics stored"). `survey-invalid` stays for inputs
that are present and wrong. A hub is a table referenced by at least `hub_min_referencing` other tables, a declared
manifest parameter (3) the code reads and the declaration publishes. A possible counter reset (the reset time moved,
or appeared where the older snapshot had none) gives no rate. Review fix (2026-10-15): Egeria 6.2's
ClassificationAnnotationProperties has only `classificationName` and `properties` of its own and ignores anything
else, so `candidateClassifications` never reaches it; `db_derived`'s classification annotation still sends it and is
dropped the same way (not fixed here).

Library pieces: `StepManifest.measure_annotation_types` (a measure published as another Egeria type), a result's
`candidate_classifications`, and `ClassificationAnnotation` in the engine host's publishable types, with the envelope in
its `additionalProperties`. Not yet done: catalog cards for the three (`generate_external_step_entries.py`), held
until the staleness fix merges, because the catalog's generated block and its test are shared with it.
