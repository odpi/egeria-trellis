why a band and not a box

Every count row inside a card already has a hairline. A box around a ruled table makes a grid of lines, and a collapsed box is a frame around one line. The card boundary is three signals stacked: space (s6 above, where rows get s1), weight (a rule-strong top rule, where rows get a hairline), and type (heading face at name size). It reads the same whether the card is open or collapsed, so collapsed cards become a clean list of bands.

how a board row truncates

At a structural boundary, never a character count. A rollup headline shows its whole-database lead, then N schemas ›. Cutting mid-list promotes whichever schema sorts first. On AdventureWorks that's hr, which holds only views, so the analysis would read as “hr: not established (no_schema_rows)…”. The server should return {lead, parts} already split. The client should never parse the sentence apart.

a prerequisite, not a design choice: “empty” is four things

_schema_inventory_container_rows puts a schema in empty when table_count == 0 or scope_state == SCOPE_EMPTY or row_total == 0 or row_total is None, and then stores "row_total": row_total or 0. So never measured becomes a stored zero, and the renderer prints it as “1 table(s) — empty”. The comment's quote of the owner's ruling has “[or, as here, no row data at all]” added inside the quote marks, but the owner ruled on zero rows. A row-count bar built on this field would draw not measured at the same height as counted, zero. This one split has to land before the overview does: row_total is None → ? “rows not measured”; == 0 → ∅ 0; table_count == 0 → “no tables”. Whether coco_pharma's three sales schemas are really zero or never measured is one query away. I've drawn them as ∅ on the assumption they're real zeros.
