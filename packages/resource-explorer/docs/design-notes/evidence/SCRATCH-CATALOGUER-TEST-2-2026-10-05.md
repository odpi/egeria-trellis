## What slice B of RE can and cannot rely on
Can rely on: one SCHEMA-kind target per chosen schema, no lists, scopes the cataloguer to exactly that schema's tables and columns and creates no database-level pass (so the leak does not exist if RE attaches only schema targets); a comma in a schema name is fine; delete (soft) of the schema element removes its tree and a re-created element is cleanly re-processed; arrays now work through a database-kind target if one is ever needed; surveys can be scoped per request with `includeSchemaNames` / `excludeSchemaNames`; per-element delete leaf-first with `forLineage` true works as the owner's user; the template gives a clean database element when `databaseDescription` and `versionIdentifier` are passed.

Cannot rely on: a removed target stopping the running connector (it needs a connector restart, which RE must not do on its own without the owner's say); archive as a leave-out (the endpoint is broken on this build, the workaround is partial without `forLineage`, and it blocks re-inclusion); the LIKE wildcard on `_`/`%` in schema and table names (RE must detect these before attaching); a cascade delete of the database or of schema-containing trees; `pct`-style names; surveying a comma-named schema; the survey reading scope from the database's connection; pooled connections closing (idle sessions stayed open 20 minutes, so DROP DATABASE needs FORCE).
