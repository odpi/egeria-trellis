# Calibration run, coco_pharma, static restore (2026-10-30)

*Kept in the repo as the record of the run. The row-by-row CSV files (profile, checks, results; 1 to 2 MB each) are not kept here. They can be produced again by running the harness `compare_re_testgen.py` from `egeria-workspaces-fs` on a restore of the same database.*

**Grade: evidence of record (plan section 6.3): a throwaway restore, one dump, no writer.**

## Run facts

- Data: `pg_dump -Fc` of coco_pharma on localhost:5442 (read-only, owner-authorised credential, once), 1,034,135 bytes, 263 tables in 29 schemas, restored into a throwaway Postgres 17 on 127.0.0.1:55438 in about 1 s. Schemas `demo` and `demo_auth` (the demo app's own tables) were left out of the TestGen groups.
- TestGen 5.134.0 (`datakitchen/dataops-testgen:v5.134.0`, the release the vendored catalogue was copied from, no catalogue skew). Metadata in a `testgen` database on the throwaway. One project, 27 table groups (one per schema), each profiled, test-generated and test-run; seeder finished with 0 failed steps. Sampling off, Standard suites only (TestGen defaults).
- RE: `origin/main` e675ed77. Throwaway SQLite registry. Profile 11.2 s with hashes on (10.9 s off); propose 1.25 s; every proposed check accepted as proposed; `run_quality_checks` 9.4 s.
- Harness `compare_re_testgen.py` unmodified, all 68 vendored types. No Egeria, no :5442 writes, no 8813.

## Profile layer (1,916 RE rows, 1,864 TestGen rows)

| Coverage | Rows |
|---|---|
| both | 1,846 |
| RE not applicable (views; RE reads tables) | 18 |
| RE only | 52 |

Of the 1,846 columns both measured, 132 are flagged different. **Every difference is explained:**

- 10 `future_date_ct`: time-relative counts. RE profiled at 14:04Z, before TestGen's per-group profiles (14:05 to about 14:20Z), and the columns hold timestamps near "now" (e.g. inv_transaction.trans_utc 1,953 vs 1,900). Not a value difference.
- 6 `min_date`/`max_date` (5 max, 1 min): the same instant; TestGen prints naive local time, RE the UTC instant (23:00 vs 04:00+00:00). A harness comparison artifact.
- 4 `distinct_value_ct`: general type X columns; RE leaves NULL ("not measured", never 0), TestGen counts. Intended.
- The rest of the 132 are the same rows flagged by those measures; `record_ct`, `value_ct`, `null_value_ct`, `zero_length_ct`, `filled_value_ct` agree on all 1,846.

## Result layer (4,750 results: 2,184 agree, 0 disagree, 2,566 not comparable)

- **2,184 agree on status** (pass 2,172, warning 10, fail 2). No Dupe_Rows xml disagreement this time: coco_pharma has no xml key columns.
- **0 disagree.**
- 2,566 not comparable: 762 TestGen passes with no RE result (the 613 plus the 149); 1,804 RE results with no TestGen test (1,004 pass, 799 `not_established`, 1 warning, from the RE-only checks above).
- RE's own run: 3,988 checks, pass 3,176, not_established 799, warning 11, fail 2.

## Findings not yet explained away

1. Valid_Characters: RE proposes it for every text column although it is `active: N` upstream (1,332 here, 96 in adventureworks). Same open divergence.
2. Sampling: TestGen's groups had sampling off; RE's sampling rule did not fire on this small database (largest table about 6,200 rows, far below the 100,000-row threshold), so this run does not test it.
3. The parameter layer (threshold_value only) was not re-examined; the same per-type comparison gap as the adventureworks run stands.

## Not covered

Table Comparison types (hashes, Match_*) and Monitor types (none generated by TestGen here); hash values; result measures value for value (status only); the `demo` and `demo_auth` schemas.
